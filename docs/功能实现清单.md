## 〇、系统基础能力（公共层）

所有模块共用的底层能力，是其余 7 个模块的地基。

| 能力 | 实现方式 |
|------|----------|
| **统一返回格式** | `Result{code, msg, data}`，前端 axios 响应拦截器统一解包 |
| **全局异常处理** | `@RestControllerAdvice` 捕获业务异常与系统异常，返回友好提示而非 500 堆栈 |
| **JWT 登录态** | Hutool 签发 HS256 令牌（7 天有效期），前端存 localStorage，请求头 `Authorization: Bearer xxx` |
| **登录拦截器** | `HandlerInterceptor` 校验令牌 → 解析用户 id/角色存入 `ThreadLocal`（`UserContext`），业务代码随处可取当前登录人 |
| **角色权限控制** | 控制器/服务层比对当前用户 `role` 与操作要求，不符抛出"只有 XX 可以操作"提示 |
| **密码加密** | BCrypt 加盐哈希存储，数据库不存明文，登录时 `BCrypt.checkpw` 比对 |
| **文件上传** | `POST /upload/image` 保存至 `backend/uploads/`，大小与类型校验，静态映射 `/uploads/**` 对外访问 |
| **分页查询** | MyBatis-Plus `Page` 分页，统一返回 `{list, total, page, size}` |
| **CORS 跨域** | `WebConfig` 配置允许前端 5173 端口访问 |
| **数据库初始化** | `db/init.sql` 幂等脚本（`CREATE TABLE IF NOT EXISTS` + 存在性判断插入），启动自动执行 |

**关键接口**

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth/register` | 注册（含角色选择，注册即登录返回令牌） |
| POST | `/api/auth/login` | 登录 |
| GET | `/api/auth/info` | 获取当前登录用户信息 |
| PUT | `/api/user/profile` | 修改基础信息（姓名/手机/头像） |
| PUT | `/api/user/password` | 修改密码（校验原密码） |
| POST | `/api/upload/image` | 上传图片 |

## 二、融资服务模块（农户侧）

**定位**：农户浏览贷款产品、发起贷款申请，核心亮点是**智能匹配联合贷款人算法**。
**涉及角色**：农户（主）、银行（数据接收方）

### 功能清单

| 功能点 | 实现说明 |
|--------|----------|
| 贷款产品一览 | 展示银行发布的贷款产品（名称/利率/额度区间/期限/说明） |
| 产品详情 | 单产品详情页 |
| 贷款申请 | 填写金额、期限、用途；**金额须在产品额度区间内**（前后端双重校验） |
| **智能匹配联合贷款人** | 提交申请前触发匹配，返回 **Top3 推荐农户**，含总分、四个维度得分、推荐理由 |
| 选择联合人 | 农户从 Top3 中选定伙伴后方可提交申请 |
| 我的融资 | 查看自己全部贷款申请及状态（待审批/已通过/已拒绝） |

### 算法一：联合贷款人匹配（`MatchService.matchPartners`）

| 维度 | 权重 | 得分计算 |
|------|------|----------|
| 信用分 | **40%** | 信用分（0-100）直接作为得分 |
| 还款能力 | **30%** | 种植面积（0-200 亩归一化）× 50% + 信用分 × 50% |
| 地域相近 | **20%** | 同市 100 分 / 同省 60 分 / 其他 20 分（从地址字符串提取市名比对） |
| 历史合作 | **10%** | 曾成功联合且申请已通过 = 100 分，否则 0 分 |

- 加权总分保留 1 位小数，**按总分倒序取 Top3**
- 每人生成**一句话推荐理由**（如"信用优秀，还款能力强，与你同市"）——体现算法可解释性
- 无档案的农户不参与匹配

### 接口与页面

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/public/loan/products` | 贷款产品列表 |
| GET | `/api/public/loan/product/{id}` | 产品详情 |
| GET | `/api/loan/partner/match` | **触发联合贷款人匹配（返回 Top3）** |
| POST | `/api/loan/apply` | 提交贷款申请（含选定的联合人） |
| GET | `/api/loan/my` | 我的融资申请列表 |

**前端页面**：[FinanceHome.vue](../frontend/src/views/finance/FinanceHome.vue)、[MyFinance.vue](../frontend/src/views/user/MyFinance.vue)
**数据表**：`loan_product`、`loan_application`、`loan_partner`、`farmer_profile`

### 技术实现要点

- 匹配在**申请前**独立调用，农户可反复查看不同结果（算法接口与申请接口解耦）
- 选定联合人写入 `loan_partner` 表（application_id, partner_farmer_id, score）

## 三、融资管理模块（银行侧后台）

**定位**：银行专属后台，核心亮点是**智能匹配农户算法**与贷款审批。
**涉及角色**：银行（非银行角色访问被拦截）
**前端布局**：独立的侧边栏后台布局（`BankLayout`），银行账号登录后自动进入

### 功能清单

| 功能点 | 实现说明 |
|--------|----------|
| 银行专属布局 | 侧边栏导航 + 顶部信息，与前台布局完全分离 |
| **角色准入拦截** | 非银行角色访问 `/bank/**` 提示"只有银行账号可以进入"并回首页 |
| 工作台统计 | 待审批数、已通过、已拒绝、已匹配农户数、在售产品数（**每 10 秒自动刷新**） |
| **智能匹配农户** | 选择贷款产品 → 返回 **Top10 推荐农户**，含总分、三维得分、推荐理由 |
| 匹配记录 | 查看历史匹配结果，可"标记已联系" |
| 贷款审批列表 | 按状态筛选申请（待审批/已通过/已拒绝），显示农户姓名电话、金额、期限、用途、联合人 |
| 审批操作 | 通过 / 拒绝（均有确认弹窗），审批后**自动通知农户** |
| 审批红点 | 侧边栏"贷款审批"显示待办数量，审批后 10 秒内自动更新 |

### 算法二：银行侧农户匹配（`MatchService.matchFarmers`）

| 维度 | 权重 | 得分计算 |
|------|------|----------|
| 信用分 | **40%** | 信用分（0-100）直接作为得分 |
| 种植规模 | **30%** | 种植面积按 0-200 亩归一化到 0-100 分 |
| 历史履约 | **30%** | 通过率 × 100 − 拒贷次数 × 15，下限 0；**无贷款记录取 60 分中性值** |

- 按总分倒序取 **Top10**
- 推荐理由按分数档位生成（信用优秀/良好/一般 + 经营规模 + 历史履约）

**与算法一的区别**（答辩对比点）：
- 算法一服务"农户找伙伴"，含地域与历史合作维度，取 Top3
- 算法二服务"银行找客户"，含经营规模与履约记录维度，取 Top10
- 两者共用"信用分"作为最高权重项，符合信贷风控"信用第一"的通用实践

### 接口与页面

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/bank/stats` | 工作台统计 |
| GET | `/api/bank/match/farmers?productId=` | **智能匹配农户（Top10）** |
| GET | `/api/bank/match/records` | 匹配记录列表 |
| PUT | `/api/bank/match/{recordId}/contact` | 标记已联系 |
| GET | `/api/bank/applications?status=` | 审批列表（按状态筛选） |
| PUT | `/api/bank/application/{id}/approve` | **审批通过**（通知农户） |
| PUT | `/api/bank/application/{id}/reject` | **审批拒绝**（通知农户） |

**前端页面**：[Dashboard.vue](../frontend/src/views/bank/Dashboard.vue)、[BankMatch.vue](../frontend/src/views/bank/BankMatch.vue)、[BankApprove.vue](../frontend/src/views/bank/BankApprove.vue)
**数据表**：`loan_application`、`match_record`、`farmer_profile`、`loan_product`

### 技术实现要点

- 匹配结果落库到 `match_record`，避免重复匹配产生重复记录（唯一性判断）
- 审批通过时回写 `bank_id`、`approve_time`，状态由 `PENDING` → `APPROVED`/`REJECTED`
- 侧边栏红点与工作台统计共用 10 秒轮询，审批后无需手动刷新

## 四、农产品交易模块

**定位**：农户与买家的产销对接，含商品管理、购物车、订单全流程、求购大厅。
**涉及角色**：农户（卖）、买家（买）

### 功能清单

| 功能点 | 实现说明 |
|--------|----------|
| 商品浏览 | 列表展示（图片/名称/价格/销量/产地），支持**关键词搜索**与分类筛选、分页 |
| 商品详情 | 价格、库存、单位、产地、供货农户、图文描述 |
| **商品管理（农户）** | 发布商品（名称/分类/价格/库存/单位/图片上传/描述）、编辑、**上架/下架切换**、删除 |
| 购物车 | 加购（库存校验）、修改数量（库存上限校验）、删除、勾选结算 |
| 下单结算 | 选择收货地址（可新增）、**按农户自动拆单**、扣减库存、下单后清空已购项 |
| 订单流转 | 待付款 → 付款 → 待发货 → 发货 → 已完成；**未发货前可取消** |
| **库存一致性** | 下单扣库存、取消恢复库存，事务保证 |
| 我的订单（买家） | 订单列表、状态、明细、付款/取消操作 |
| 供货订单（农户） | 查看卖给自己商品的订单（含买家与收货地址）、发货操作 |
| **求购大厅** | 买家发布采购需求（品名/分类/数量/预算/截止日期/描述）、管理自己的需求（改状态/删除） |
| 联系买家 | 农户在求购大厅点击"联系买家"，弹出买家姓名与电话 |

### 接口与页面

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/public/products` | 商品列表（搜索/分类/分页） |

| GET | `/api/product/my` | 我的商品（农户） |
| POST | `/api/product/save` | 发布/编辑商品（农户） |
| PUT | `/api/product/{id}/status` | 上架/下架 |
| DELETE | `/api/product/{id}` | 删除商品 |
| GET | `/api/cart/list` | 购物车列表 |
| POST | `/api/cart/add` | 加入购物车（买家） |
| PUT | `/api/cart/{id}/quantity` | 修改数量 |
| DELETE | `/api/cart/{id}` | 删除购物车项 |

| GET | `/api/order/my` | 我的订单（买家） |
| GET | `/api/order/seller` | 供货订单（农户） |

**前端页面**：[MarketHome.vue](../frontend/src/views/market/MarketHome.vue)、[ProductDetail.vue](../frontend/src/views/market/ProductDetail.vue)、[Cart.vue](../frontend/src/views/market/Cart.vue)、[OrderList.vue](../frontend/src/views/market/OrderList.vue)、[DemandList.vue](../frontend/src/views/market/DemandList.vue)
**数据表**：`product`、`cart`、`orders`、`order_item`、`demand`、`address`

### 技术实现要点

- **订单状态机**：`PENDING(待付款) → PAID(待发货) → FINISHED(已完成)`，分支 `CANCELED(已取消)`
  - 可取消条件：未发货（待付款或待发货状态）
  - 取消时逐项恢复商品库存
- **按农户拆单**：购物车中不同农户的商品在下单时生成**多张订单**（每农户一张），保证农户只能看到与自己相关的订单
- **事务保证**：下单（校验库存 → 扣库存 → 生成订单与明细 → 清购物车）在同一事务内，任一步失败整体回滚，防止超卖
- **下单不通知、付款才通知**：避免买家下单后不付款造成农户无效打扰（产品设计上的取舍）

| GET | `/api/consult/list?withUserId=` | 与某人的会话消息 |
| GET | `/api/consult/contacts` | 联系人列表 |
| GET | `/api/consult/stats` | 未读消息/未读通知统计 |

**前端页面**：[ExpertHome.vue](../frontend/src/views/expert/ExpertHome.vue)、[KnowledgeList.vue](../frontend/src/views/expert/KnowledgeList.vue)、[KnowledgeDetail.vue](../frontend/src/views/expert/KnowledgeDetail.vue)、[QuestionList.vue](../frontend/src/views/expert/QuestionList.vue)、[ExpertList.vue](../frontend/src/views/expert/ExpertList.vue)、[Chat.vue](../frontend/src/views/expert/Chat.vue)、[Appointments.vue](../frontend/src/views/expert/Appointments.vue)
**数据表**：`article`、`question`、`answer`、`appointment`、`consult_message`、`expert_profile`

### 技术实现要点

- **轮询而非 WebSocket**：3 秒轮询实现简单可靠，满足演示与中小规模使用；WebSocket 是明确的升级方向
- **已读机制**：进入会话时批量标记对方发来的消息为已读，红点消失
- **问答的双向删除**：专家删回答 → 问题状态回退；农户删问题 → 级联删除回答
- 预约状态：`待确认 → 已确认 → 已完成`，另有 `已取消` 分支

## 七、通知中心模块

**定位**：贯穿三条业务线的全局消息汇聚点，是演示时三个业务闭环收尾的关键。
**涉及角色**：全部

### 功能清单

| 功能点 | 实现说明 |
|--------|----------|
| 铃铛红点 | 顶栏铃铛图标显示未读数量（**10 秒轮询**） |
| 通知列表 | 下拉展示通知（标题/内容/时间），未读高亮 |
| 点击跳转 | 点击通知**自动标记已读并跳转对应业务页** |
| 全部已读 | 一键清空未读数 |
| 银行侧红点 | 银行后台侧边栏"贷款审批"显示待办数量（10 秒轮询） |

### 六类通知事件

| 类型 | 触发时机 | 接收人 | 跳转目标 |
|------|----------|--------|----------|
| `LOAN_APPROVED` | 银行审批通过 | 农户 | 我的融资 |
| `LOAN_REJECTED` | 银行审批拒绝 | 农户 | 我的融资 |
| `ORDER_PAID` | 买家付款成功 | 供货农户 | 供货订单（待发货） |
| `ORDER_SHIPPED` | 农户发货 | 买家 | 我的订单 |
| `QUESTION_ANSWERED` | 专家提交回答 | 提问农户 | 问答详情 |
| `APPOINTMENT_HANDLED` | 专家确认/完成预约 | 预约农户 | 我的预约 |

> 说明：买家下单时**不**发通知，付款后才通知农户——避免未付款订单打扰农户。

### 接口与页面

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/notify/list` | 通知列表 + 未读数 |
| PUT | `/api/notify/{id}/read` | 标记单条已读 |
| PUT | `/api/notify/read-all` | 全部已读 |
| GET | `/api/consult/stats` | 未读消息与未读通知合并统计（红点数据源） |

**前端页面**：[FrontLayout.vue](../frontend/src/layouts/FrontLayout.vue)（顶栏铃铛）、[BankLayout.vue](../frontend/src/layouts/BankLayout.vue)（侧边栏红点）
**数据表**：`notification`

### 技术实现要点

- `NotificationService.send(userId, type, title, content, relatedId)` 是**唯一入口**，所有业务模块通过它发通知，`relatedId` 记录关联业务 id 供跳转定位
- 轮询策略：10 秒间隔，`onUnmounted` 时清理定时器防止内存泄漏
