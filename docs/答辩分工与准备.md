# 融小通平台 · 5 人小组分工与答辩准备指南

## 一、五人分工方案（亮点均衡版 · 答辩优化）

> 原则：每人负责"完整闭环"（自己模块的数据库表 + 后端接口 + 前端页面），
> **且每人都有一个可现场演示的功能 + 一个可深入讲解的技术点**——保证老师在答辩中问到谁，谁都有料可讲。

| 成员 | 职责 | 具体内容 | 答辩时的"演示点" | 答辩时的"技术点" |
|------|------|----------|-----------------|-----------------|
| **① 组长 / 架构师** | 框架 + 用户系统 + 首页 + **通知中心** | 前后端项目搭建、统一返回/全局异常、**JWT 登录注册与权限拦截**、四角色体系、首页六大板块、**全局通知中心（铃铛红点，三条业务线演示的最后汇聚点）**、README 与环境部署 | 开场登录 + 角色差异化跳转 + 铃铛红点 | 系统架构、JWT 令牌原理、BCrypt 加密、通知轮询机制 |
| **② 融资业务负责人** | 融资服务（农户侧） | 贷款产品、贷款申请、**智能匹配联合贷款人算法**（信用40%+还款30%+地域20%+合作10%，Top3+推荐理由）、我的融资 | 现场申请贷款，展示 Top3 匹配动画 | 算法一：四维评分模型与权重依据 |
| **③ 银行侧负责人** | 融资管理后台（银行侧） | 银行专属布局、工作台统计、**智能匹配农户算法**（信用40%+规模30%+履约30%，Top10）、贷款审批、**银行角色权限拦截** | 接在 ② 后面审批贷款，形成闭环 | 算法二（与算法一对比讲）+ 角色权限设计 |
| **④ 农产品交易负责人** | 农产品交易 | 商品浏览/搜索/详情、商品管理、购物车、下单结算（按农户拆单、**扣库存/取消恢复**）、订单状态流转、求购大厅 | 加购→下单→付款→发货完整交易闭环 | 订单状态机、库存一致性（事务） |
| **⑤ 农技服务负责人** | 专家助力 + 个人中心 | 知识库、在线问答、专家团队、**消息聊天（轮询）**、预约处理、个人中心（**头像上传**、收货地址、改密码、**按角色聚合的菜单**）、管理员用户管理 | 提问→回答→通知、预约→处理、聊天 | 消息轮询机制、文件上传、一套菜单四种角色的权限设计 |

### 协作方式建议

- **①②③ 是"融资组"**：② 的农户申请数据是 ③ 的审批输入，两人约定好接口字段后并行开发
- **④⑤ 相互独立**：交易线和农技线无数据耦合，可完全并行
- **组长负责集成**：每阶段合并代码、解决冲突（本项目已按阶段 git 提交，可讲解版本管理）
- 数据库设计表结构由 **① 牵头全体讨论**，每人负责自己模块的建表语句与种子数据

## 二、答辩 PPT 大纲（建议 10~12 页）

1. **封面**：项目名、组员分工（对应上表）
2. **项目背景与意义**：三农痛点（融资难、销售渠道少、缺技术指导）→ 平台定位
3. **需求分析**：4 类角色、3 条业务线、7 大模块（画角色-业务矩阵图）
4. **总体架构**：前后端分离架构图（Vue 3 ↔ Axios ↔ Spring Boot ↔ SQLite）、技术选型理由
5. **数据库设计**：核心表 ER 图或表清单（18+ 张表，按业务分色块）
6. **核心亮点一：联合贷款人匹配算法**（② 讲：评分公式、四维权重、Top3 结果截图）
7. **核心亮点二：银行侧农户匹配算法**（③ 讲：三维权重、与算法一对比）
8. **关键流程设计**：订单状态机（待付款→待发货→已完成/取消+库存恢复）、通知机制
9. **安全设计**：JWT 令牌、BCrypt 密码加密、角色权限拦截、文件上传校验
10. **系统演示**（现场演示或录屏）
11. **项目总结与展望**：收获、可扩展方向（WebSocket 实时聊天、真实支付、地图定位、信用评估模型）

## 四、答辩高频问题准备（提前想好答案）

| 老师可能问 | 答题思路 |
|-----------|----------|
| 为什么用 SQLite 而不用 MySQL？ | 免安装、单文件、便于演示与部署；代码已分层，改一行配置 + 换驱动即可迁移 MySQL（README 已写） |
| 匹配算法的权重为什么是 40/30/20/10？ | 参考信贷评估通用实践：信用是风控第一要素权重最高；答辩时强调"规则可解释、可调整" |
| 算法和"智能"有什么关系？ | 是规则可解释的加权评分模型（非机器学习），实际业务中可解释性比黑盒模型更重要；后续可引入机器学习替换评分函数 |
| 密码安全怎么做？ | BCrypt 加盐哈希，数据库不存明文；登录态用 JWT 7 天过期；接口层拦截器校验 + 角色判断 |
| 订单超卖怎么办？ | 下单时校验库存并扣减、取消恢复，事务保证一致性；演示可提 SQLite 单文件并发限制的局限与 MySQL 的升级空间 |
| 聊天为什么不用 WebSocket？ | 当前用 3 秒轮询实现简单可靠、足够演示；WebSocket 是明确的可扩展方向 |
| 你负责的部分是什么？ | **每人必须能独立回答**：自己的模块、自己写的表和接口、遇到的坑（如 vue-router 5 空路径 redirect 的坑、上传相对路径的坑——讲"我踩过什么坑、怎么解决的"非常加分） |
