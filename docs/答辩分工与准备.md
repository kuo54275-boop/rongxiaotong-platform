# 融小通平台 · 5 人小组分工与答辩准备指南

## 一、五人分工方案（按业务模块划分）

> 原则：每人负责"完整闭环"——即自己模块的 **数据库表 + 后端接口 + 前端页面**，
> 答辩时各讲各的部分，边界清晰、工作量均衡。

| 成员 | 职责 | 具体内容 | 答辩时主讲 |
|------|------|----------|-----------|
| **① 组长 / 架构师** | 项目框架 + 用户系统 + 首页 | 前后端项目搭建（Spring Boot 3 + Vue 3 工程）、统一返回/全局异常、**JWT 登录注册与权限拦截**、四角色体系、首页六大板块聚合接口、README 与环境部署 | 需求分析、总体架构图、登录权限流程 |
| **② 融资业务负责人** | 融资服务（农户侧） | 贷款产品一览、贷款申请、**智能匹配联合贷款人算法**（信用分 40% + 还款能力 30% + 地域 20% + 历史合作 10%，Top3 + 推荐理由）、我的融资 | 算法一：联合贷款人匹配（重点讲评分模型与权重依据） |
| **③ 银行侧负责人** | 融资管理后台（银行侧） | 银行专属布局、工作台统计、**智能匹配农户算法**（信用分 40% + 种植规模 30% + 历史履约 30%，Top10）、贷款审批（通过/拒绝 + 农户通知） | 算法二：银行匹配农户（与②对比讲解，体现算法差异化） |
| **④ 农产品交易负责人** | 交易 + 通知 | 商品浏览/搜索/详情、农户商品管理、购物车、下单结算（按农户拆单、**扣库存/取消恢复**）、订单状态流转、求购大厅、**全局通知中心**（红点提醒） | 交易全流程演示、库存与订单状态机、通知机制 |
| **⑤ 农技服务负责人** | 专家助力 + 个人中心 | 农业知识库（浏览+专家维护）、在线问答（提问/回答/删除）、专家团队（介绍/咨询/**消息聊天**/预约处理）、个人信息中心（头像上传、收货地址、改密码、我的发布、专家信息管理、**管理员用户管理**） | 农户↔专家协作闭环、角色化个人中心 |

### 协作方式建议

- **①②③ 是"融资组"**：② 的农户申请数据是 ③ 的审批输入，两人约定好接口字段后并行开发
- **④⑤ 相互独立**：交易线和农技线无数据耦合，可完全并行
- **组长负责集成**：每阶段合并代码、解决冲突（本项目已按阶段 git 提交，可讲解版本管理）
- 数据库设计表结构由 **① 牵头全体讨论**，每人负责自己模块的建表语句与种子数据

## 二、答辩 PPT 大纲（建议 10~12 页）

1. **封面**：项目名、组员分工（对应上表）
2. **项目背景与意义**：三农痛点（融资难、销售渠道少、缺技术指导）→ 平台定位
3. **需求分析**：4 类角色、3 条业务线、7 大模块（画角色-业务矩阵图）
4. **总体架构**：前后端分离架构图（Vue 3 ↔ Axios ↔ Spring Boot ↔ SQLite）、技术选型理由
5. **数据库设计**：核心表 ER 图或表清单（18+ 张表，按业务分色块）
6. **核心亮点一：联合贷款人匹配算法**（② 讲：评分公式、四维权重、Top3 结果截图）
7. **核心亮点二：银行侧农户匹配算法**（③ 讲：三维权重、与算法一对比）
8. **关键流程设计**：订单状态机（待付款→待发货→已完成/取消+库存恢复）、通知机制
9. **安全设计**：JWT 令牌、BCrypt 密码加密、角色权限拦截、文件上传校验
10. **系统演示**（现场演示或录屏）
11. **项目总结与展望**：收获、可扩展方向（WebSocket 实时聊天、真实支付、地图定位、信用评估模型）

## 三、答辩演示剧本（5 分钟，最有视觉冲击力的部分）

> 准备两台浏览器窗口（或一个窗口切换账号），按顺序走：

1. **登录 farmer01（农户）**：介绍首页 → 融资服务 → 申请贷款 → **展示联合贷款人 Top3 推荐**（算法一亮相）
2. **登录 bank01（银行）**：自动进入后台 → **智能匹配农户 Top10**（算法二亮相）→ 审批刚才的申请（通过）
3. **切回 farmer01**：铃铛红点 → 审批通过通知 → 我的融资状态更新（闭环！）
4. **登录 buyer01（买家）**：浏览商品 → 加购物车 → 下单 → 付款
5. **切回 farmer01**：新订单通知 → 发货 → 买家收到发货通知（第二个闭环！）
6. **登录 expert01（专家）**：回答问题 → 农户收到回答通知；处理预约（第三个闭环！）

> ⚠️ 建议**提前录一份演示视频备用**：答辩现场可能出现投影故障、网络问题、电脑卡顿，
> 视频兜底是最稳的保险。

## 四、答辩高频问题准备（提前想好答案）

| 老师可能问 | 答题思路 |
|-----------|----------|
| 为什么用 SQLite 而不用 MySQL？ | 免安装、单文件、便于演示与部署；代码已分层，改一行配置 + 换驱动即可迁移 MySQL（README 已写） |
| 匹配算法的权重为什么是 40/30/20/10？ | 参考信贷评估通用实践：信用是风控第一要素权重最高；答辩时强调"规则可解释、可调整" |
| 算法和"智能"有什么关系？ | 是规则可解释的加权评分模型（非机器学习），实际业务中可解释性比黑盒模型更重要；后续可引入机器学习替换评分函数 |
| 密码安全怎么做？ | BCrypt 加盐哈希，数据库不存明文；登录态用 JWT 7 天过期；接口层拦截器校验 + 角色判断 |
| 订单超卖怎么办？ | 下单时校验库存并扣减、取消恢复，事务保证一致性；演示可提 SQLite 单文件并发限制的局限与 MySQL 的升级空间 |
| 聊天为什么不用 WebSocket？ | 当前用 3 秒轮询实现简单可靠、足够演示；WebSocket 是明确的可扩展方向 |
| 你负责的部分是什么？ | **每人必须能独立回答**：自己的模块、自己写的表和接口、遇到的坑（如 vue-router 5 空路径 redirect 的坑、上传相对路径的坑——讲"我踩过什么坑、怎么解决的"非常加分） |
